# 小鱼创作台 · dsh-xiaoyu-novel

[中文](README.md) | [English](README.en.md)

> 一支替你守稿的笔。

小鱼创作台是 **DSH（DeepSeek Harness）** 里的网文创作辅助插件。装上之后，你的 AI 主助手不再是一个什么都聊的对话框，而是一位**网文主编**：它带大纲师、写手、去 AI 味师、审校、设定管理员、素材调研员六个帮手，一起把一部长篇从选题写到完结。

整本书就是工作区里的一个 `novel/` 目录——纯 markdown 与 YAML，没有数据库，没有 API 层，没有迁移。想查「所有还没回收的伏笔」，就是 grep 一行的事。

**版本**：3.25.1 ｜ **许可**：MIT ｜ **运行时依赖**：零 ｜ **兼容**：Windows / macOS / Linux / Android 上的 DSH Web

## 它解决什么问题

用 AI 写长篇，卡人的从来不是「写不出一章」，而是这几件事：

| 痛点 | 小鱼的解法 |
|---|---|
| 写到第 80 章，AI 忘了前面埋的伏笔 | **伏笔状态机**：埋设 → 推进 → 回收/弃用，每条记章节号与预期回收章，账本随时查 |
| 角色今天黑眼睛明天红头发 | **连续性体检**：角色卡属性与正文描述自动比对，时间线倒流自动报错 |
| 设定写了几十页，写手从来不看 | **活设定集**：设定被引用就打时间戳，按最近使用排序，没人用的自动沉底 |
| 每章像流水线生成的 | **逐章去 AI 味门禁**：人味指数不到线就打回重写，五项检测器视角逐条卡 |
| 动笔就跑偏，章尾没钩子 | **章节蓝图**：先写小目标/冲突转折/章尾钩子，三填齐才准开写 |
| 读者不知道的事，正文提前泄底 | **信息差警戒**：读者未知的伏笔，正文、对话、心理活动一律禁提 |
| 发出去被平台拦 | **合规体检**：三级敏感词库（拒绝级/风险级/提示级）逐章扫描 |
| 不知道现在什么题材火 | **题材雷达**：番茄公开榜单聚合成题材排行，断网也有上次快照 |

## 安装

### 方式一：面板导入（推荐）

1. 从 [Releases](https://github.com/gqpG10/dsh-xiaoyu-novel/releases) 下载最新的 `dsh-xiaoyu-novel-x.y.z.zip`
2. 在 DSH 里执行 `dsha-plugin import <zip 路径>`
3. 重启 DSH Web

### 方式二：命令行

```bash
dsha-plugin import ./dsh-xiaoyu-novel-3.25.1.zip
```

装好后，左侧栏面板列表会出现**小鱼创作台**，点开即用。

## 五分钟上手

```bash
# 1. 建一本书（在工作区里生成 novel/ 目录，九个面全部就位）
xiaoyu-novel init ./我的书

# 2. 检查开书清单是否填齐（缺项退出码 1）
xiaoyu-novel setup ./我的书

# 3. 把 novel/ 登记成 DSH 工作区（也可在面板顶部「接入项目」里点）
xiaoyu-novel handoff ./我的书
```

然后在 DSH 里对主编说一句：**「用小鱼创作台，把《我的书》的设定补完，然后写第一章」**。

主编会按阶段推进：选题 → 设定 → 大纲 → 写作 → 审阅 → 一致性 → 导出，每个里程碑向你汇报一次，需要拍板的地方（设定一览、分卷规划）会停下来等你。

|---|---|
| **概览** | 书稿元信息、分卷规划、今日新增字数、近 120 天写作热力格、连续更新天数 |
| **项目** | project.yml 表单化编辑；**题材雷达**（番茄榜单聚合）；拍板账 |

| **门禁** | 逐章人味指数、批量修复、**合规体检**卡、重点章节定位 |
| **体检** | **六维质量趋势**（人味/爽点/钩子/节奏/一致性/追读力六线走势 + 追读力预警）、**连续性体检**（属性矛盾/时间倒流）、跨章重复、角色 0 出场、字数离群、章末平收 |
| **待办** | 问题清单与勾选 |
| **本章** | 写这一章前必看：命中角色、到期伏笔、背景伏笔、**泄底警戒**、**前情摘要**、**章节蓝图**（三填表单 + 定稿生成章记忆）、**本章上下文包** |

| **伏笔** | 伏笔账本，状态机流转，待回收排期 |
| **关系** | 关系图（力导向布局，带漂移治理）、关系去重维护 |
| **时间线** | 时间线视图与编辑 |
| **设定** | 世界观 / 科学设定 / 考据，**活设定集**（按最近使用排序 + 标记已用） |

## 写作流程

### 七阶段工作流

`idea 选题 → setting 设定 → outline 大纲 → writing 写作 → review 审阅 → consistency 一致性 → export 导出`

阶段记在 `novel/project.yml` 的 `phase` 键。推进有硬判据（核心设定落盘、分卷规划与前三章大纲在案才准进 writing），不满足就退回补齐。

### 写作七步法（逐章循环）

1. **衔接检查** —— 读上一章结尾与本章章纲
2. **出蓝图** —— 小目标 / 冲突转折 / 章尾钩子（面板「本章」tab 表单）
3. **写正文** —— 写手出手，只拿本章需要的角色与伏笔
4. **去 AI 味** —— 交给去 AI 味师改稿，改前改后各跑一次扫描器
5. **审稿** —— 审校按七层清单挑错
6. **修改** —— 按清单改
7. **定稿维护** —— 回写伏笔、角色状态、时间线、章记忆（面板一键「定稿·生成章记忆」）

### 主编 + 六帮手

| 角色 | 干什么 |
|---|---|
| **主编（主 agent）** | 规划、衔接、验收、状态推进 |
| 大纲师 outline | 卷纲、章纲、节奏曲线 |
| 写手 draft | 按蓝图与上下文写正文 |
| 去 AI 味师 polish | 十二式手术，去套话、拆长句、补体感 |
| 审校 review | 七层清单逐项挑错（只读） |
| 设定管理员 lore | 维护角色卡、设定、伏笔、关系、时间线 |
| 素材调研员 research | 联网考据，区分史实/通说/演义并附来源 |

## novel/ 目录结构

```
novel/
├── project.yml          书稿元信息（书名/题材/阶段/模式）
├── volumes.yml          分卷规划
├── chapters/            正文，一章一文件（v01-c001.md）
├── outlines/            章纲，与正文同名配对
├── characters/          角色卡
├── world/               世界观设定（活设定集）
├── science/             科学/技术设定
├── research/            考据笔记（带来源）
├── foreshadows.yml      伏笔账本（状态机）
├── relations.yml        人物关系账
├── timeline.yml         时间线
├── clue-board.yml       线索板
├── decisions.yml        拍板账
├── memories.yml         叙事记忆
├── index.yml            章节索引
├── style.md             写作风格基线
├── blueprints/          章节蓝图（3.22.0+）
├── memory/              章后记忆摘要（3.23.0+）
├── reports/             体检报告、题材雷达快照
└── exports/             导出成品
```

全部是 grep 友好的 YAML 与 markdown —— 人可以直接改，git 可以版本化，换电脑拷走就能继续写。

## 语言风格档位

`templates/novel/style-presets/` 内置 19 档风格（面板「风格」tab 可一键套用）：

- **商业向**：`fanqie`（番茄）、`qidian`（起点）、`qimao`（七猫）、`fast`（快节奏）、`plain`（大白话）、`humor`（搞笑）、`tomatohumor`（番茄沙雕）、`suspense`（悬疑）、`tianchong`（天蚕土豆风）、`zhongtian`（中天）等
- **文学向**：`classical`（古典）、`epic`（史诗）、`romance`（言情）、`nuelian`（虐恋）、`warm`（温情）、`niandai`（年代）、`guize`（规则怪谈）、`semi`（半文半白）、`minimal`（极简）

每档都写清了句长、段落、对话密度、禁用句式与章末钩子的具体约束，不是一句形容词。

## 质量工具

### 去 AI 味门禁

每章正文写完先过一遍，改前改后各跑一次自带扫描器（`skills/xiaoyu-qu-ai-wei/scripts/aiwei_scan.py`）：

- **人味指数** < 78 或出现硬伤维度 → 打回重改
- 五项目视角：句长突变度 ≥ 0.55 ｜ 连接词 ≤ 6/千字 ｜ 四字格 ≤ 1.5/千字 ｜ 口语标记 ≥ 5/千字 ｜ 标点种类 ≥ 6
- 只改写法，不动情节、对话语义与伏笔点位，字数浮动 ≤ 10%

### 六维质量趋势

人味 · 爽点 · 钩子 · 节奏 · 一致性 · 追读力，逐章打分画六线走势；连续三章追读力均值低于 45 自动预警。

### 合规体检

三级敏感词（拒绝级 / 风险级 / 提示级）逐章扫描，命中带上下文；词库可用 `novel/compliance.yml` 自定义扩充。

### 连续性体检

角色卡属性 vs 正文描述（红瞳被写成黑眼自动报）、时间倒流（第 1 章引用第 5 章的事）。

### 全书体检

跨章重复片段、角色 0 出场、章纲点名未落地、字数离群、连续平收，一键成报告。

## 更新与国内加速

面板设置里有「检测更新」，三通道并行竞速：

- GitHub REST API（带令牌）/ 匿名 API / raw 主分支 / 四个公共镜像 / **Gitee tags**

谁先响应谁赢，单源 8 秒收敛。下载同样四通道竞速（REST tarball / codeload / 镜像链 / Gitee archive），第一个校验通过的落盘。

GitHub 被墙时，Gitee 通道仍然可用——这也是本仓库在 Gitee 上同步一份的原因。

环境变量逃生阀：

```bash
XIAOYU_GITHUB_REPO=off      # 只用 Gitee
XIAOYU_GITEE_REPO=off       # 只用 GitHub
XIAOYU_GH_MIRRORS=...       # 覆盖镜像链
```

## 常见问题

**Q：需要额外装 Python 吗？**
去 AI 味扫描器（`aiwei_scan.py`）需要 Python 3。没有也能用，面板会标注「python3 缺失，分数不可用」，其余功能不受影响。`xiaoyu-novel doctor` 可以体检。

**Q：手机上能用吗？**
能。面板是独立单页，手机竖屏布局专门适配过；Windows 与 Android 上的 DSH 都跑同一套测试。

**Q：我的书稿在哪？**
在你自己的工作区 `novel/` 目录里，纯文本。插件不碰云、不上传、不改格式，拷走就能继续写。

**Q：能直接发番茄/起点吗？**
插件不发布章节、不碰作者后台。合规体检是发之前的自查工具；导出支持 txt / docx / epub。

**Q：会不会改乱我的稿子？**
所有写操作有前置校验（格式、结构、哈希），编辑外部改过会 409 拒写，章节有版本快照可撤销；`ledger clean` / `relations` 默认 dry-run，`--apply` 才落盘且写前备份。

## 名字与致谢

### 名字

「小鱼」是本插件自己的名字，取「笔」之意。写小说的人都知道，真正干活的从来不是灵感，是那支被攥得发烫的笔。

（至于「韩愈《小鱼传》」那个说法——韩愈写的是《毛颖传》，喻毛笔「毛颖」，封管城子，跟「小鱼」没有半点关系。以讹传讹的典故，作者一概不背。）
