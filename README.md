# dsh-xiaoyu-novel（小鱼）

中文 | [English](README.en.md)

小鱼者，笔也——韩愈作《小鱼传》，把一支毛笔写成有封地有爵位的臣子。dsh-xiaoyu-novel 把这支笔装进 DSH（DeepSeek Harness）：**一支管着一班帮手、守着一摞书稿的毛笔**——网文创作辅助插件，全部实现原创，MIT 发布。

装上之后，主 agent 变身**网文主编（创作总监）**：带七阶段工作流与七步写作法（逐章含去 AI 味门禁），把大纲、正文、去 AI 味、审校、设定维护、素材考据分别委派给六个只带本行工具的帮手；整部小说就是工作区里的 `novel/` 结构化 markdown/YAML 目录（角色卡、伏笔状态机、时间线、线索板、叙事记忆）——agent 直接读写文件，**没有数据库，没有 API 层**。查「所有未回收伏笔」就是 grep 一行。
- **开书九件套（硬性）**：新书必须先把概览/章节/角色/伏笔/关系/时间线/设定/写作风格/章节索引（index.yml）九个面填实才开写；面板概览「开书清单」逐项 ✓/缺、点行跳对应 tab，CLI `xiaoyu-novel setup` 同一判据（缺项退出码 1）。连载期每章收尾同步维护被本章动到的面，缺件补建。
- **格式只认模板**：键名、键序、`---` 围栏、缩进、数组写法、枚举全称一律照 `templates/novel/`；`xiaoyu-novel check` 与面板静态体检新增格式硬校验（未知键、缺字段、键序偏差、围栏未闭合、文件名不合规、索引与目录不一致），不照模板就报出来。

## 功能特性

- **主编 + 六帮手**：主 agent 当主编，只做规划、衔接、验收、状态推进；大纲师（outline）、写手（draft）、去 AI 味师（polish）、审校（review）、设定管理员（lore）、素材调研员（research）各带本行工具随叫随到。找文件、查伏笔状态这类顺手小事主编自己 glob/grep 就办，不绕委派。
- **novel/ 文件数据库**：角色卡、世界观、科学设定三色标注、关系图、伏笔账本、时间线、叙事记忆、线索板、拍板账，全部是 grep 友好的平键/顶层数组 YAML——人可直接改，git 可版本化，无迁移无运维。关系图的类型配色/方向/阶段/标签全是可选字段，不写就退回旧行为。
- **七阶段工作流**：idea 选题 → setting 设定 → outline 大纲 → writing 写作 → review 审阅 → consistency 一致性 → export 导出。阶段记在 project.yml 的 phase 键，每完成一个里程碑主编推进并简报；推进有完成判据（核心设定落盘、分卷规划与目标章大纲在案才进 writing），不满足就回上一阶段补齐。
- **Writing 七步法**：衔接检查 → 出大纲 → 写正文 → 去 AI 味（polish）→ 审稿 → 修改 → 定稿维护，逐章循环；配合 Collab 四步共创（设定共创 → 分卷规划 → 黄金三章 → 交接循环）把新书从零带到滚动更新；设定一览与分卷规划各设一个用户拍板点，前三章在设定齐备前不开工。
- **逐章去 AI 味门禁**：每章正文写完先交去 AI 味师（polish）改稿——按十二式手术与每千字配比表删套话、拆长句、补具体与体感，改前改后各跑一次自带扫描器（skills/xiaoyu-qu-ai-wei/scripts/aiwei_scan.py），人味指数 <78 或出现硬伤维度就打回重改；再过检测器视角五项（句长突变度 ≥0.55、连接词 ≤6/千字、四字格 ≤1.5/千字、口语标记 ≥5/千字、标点种类 ≥6）。只改写法，不动情节、对话语义与伏笔点位，字数浮动 ≤10%。
- **白话文基线与梗规则**：写手默认白话文（口语、短句、能上口），禁书面腔与翻译腔；文言只做点缀（古风人物、公文判词、书信题跋），一章不超过三处、每处一句；梗要原创且贴人物身份与处境，一章两三个封顶，不解释不标注；冷启动时定语言档位（大白话（默认）/ 文白相间 / 古风 / 番茄沙雕搞笑等 11 档，见 templates/novel/style-presets/），一套预设适配多题材。番茄沙雕档写的是「手机备忘录随手码字」的手感：句长错落、段落别匀、主角嘴碎、配角有脾气、笑点埋在动作和对话里、章末三行勾人，禁三连排比与「空气仿佛凝固」。
- **伏笔状态机**：planted（埋设）→ progressing（推进）→ resolved（回收）/ abandoned（弃用），埋设与回收记章节号、预期回收章节排期、优先级分档——长篇不断线，活跃伏笔超 15 条主编主动提醒清理。
- **上下文按需取**：主编先读 index.yml 概览，写到哪章读哪章（前章结尾约 1500 字 + 该章大纲 + 出场角色卡 + 活跃伏笔节选），不把整本书塞进上下文。
- **工具面收窄**：主编只见「角色委派 + 内部检索 + 协调」白名单，帮手各带本行工具（审校只读、考据只带联网+落笔记）；每次请求的工具开销与上下文占用随之下降。
- **素材考据**：research 帮手联网检索历史/地理/专业领域素材，笔记落 `novel/research/`，区分史实/通说/演义并附来源——DSH 架构的红利。
- **创作台面板**：DSH 侧栏一键打开的可视化创作台——默认中栏全页面板，也可按「打开方式」设置整体搬进右侧栏（分栏：创作台中栏 + 文章页右侧栏 tab / 中间栏 / 右侧栏三选一，宿主 0.2.x 支持右侧栏）——概览（含书稿元信息编辑与分卷规划）/章节/角色/伏笔/关系图/时间线/设定/写作风格/索引板九个 tab；章节整页阅读（章纲对照 + 正文/章纲编辑保存 + 五维 + 状态流转）、project.yml 表单化编辑、写作风格查看与编辑（缺失时用默认基线创建）、账本与实体卡的人工编辑写面（编辑/新建/删除，带结构校验与确认弹层）、顶栏字号六档缩放、界面语言中文/English 可切与自动新版检测；章节列表与阅读页直接显示该章门禁分（人味指数 / 人写度），阅读页可一键复制交给主编的去 AI 味委派指令、逐句建议带「改」一键微调、整章「改」一次批量保守修（弹层确认后覆盖原文并重算分数，可「撤销」按快照恢复）；章末平收（网文钩子缺失）在门禁徽标上直接提示；章节表可按门禁分排序、顶部门禁趋势折线（门禁线点一下循环切换 78/82/86/90，写进 novel/xiaoyu.json）；「全书体检」一键查跨章重复、角色 0 出场、章纲点名未落地、字数离群与连续平收，报告导出到 novel/reports/；阅读页「复制全章」一次复制「章节名 + 正文」；概览显示今日新增字数；写作风格 tab 可一键套用语言档位；接入项目改为内联输入（不依赖原生弹窗）；顶部「接入项目」把已有 novel/ 目录登记为工作区；阅读页门禁分带与上次的差值；展开「去 AI 味建议」看逐句病灶（套话/长句/并列/破译）。
- **2.6.0：内嵌凭据换成 fine-grained 只读令牌**（0.21.0）
  - 内嵌的是 **fine-grained PAT，只授本仓库 `Contents: Read`**：可读版本与源码包，**写不了**（建分支 403）、**别的库读不到**（404）。已实测确认。
  - 修 `inspectToken` 的写权限判据——两次判错都出在「先校验参数、后校验权限」：
    ① `GET /repos` 的 `permissions` 字段在 fine-grained 下反映的是**账号**权限，只读令牌照样回 `admin:true`；
    ② `POST /git/refs` 空 body 一定 422（缺 ref/sha），只读令牌也被误判成可写；
    ③ 现在用**参数合法**的建 ref 尝试：403 = 没写权限，201 = 有（成功后立刻 DELETE，`probeCleaned` 带回是否清理干净）。三种判据的实测差异都写进注释与测试了。
  - 只读令牌跑通全链路：查版本 → 下 669KB 源码包 → 解压 → 校验 → 备份 → 覆盖，1.0.0 → 2.6.0 共 **4.9 秒**（比 OAuth 全权令牌还快）。
- **2.5.1：凭据收成最小权限——代码层三道硬边界 + 一键换令牌 + 体检**（0.20.0）
  - **三道硬边界**（写在 `lib/github-token.mjs` 里，发请求前就拦，不靠自觉）：
    ① 只许发 `api.github.com` / `codeload.github.com`（临时用别的 URL 直接拒绝发凭据）；

  - **换令牌**：`xiaoyu-novel token set <PAT>` —— 先体检新令牌（读目标库？能写？能读别的库？），通过后只重写 `lib/github-token.mjs` 的 `PARTS` 数组，其余一字不动，原文件存 `.bak`。

  - 测试 **230 → 234**（新增：硬边界白名单/方法/钉库；换令牌往返与不改其他内容；**钉库守卫按解出来的凭据判断**——第一版只看入参，空入参能用内嵌凭据读别的库，实测发现并修掉；体检不用写探针）。

- **关系图做完整了**（0.9.0）：关系类型配色/线型（对立红、同盟蓝、亲友绿、雇佣灰、师徒紫、暧昧粉虚线……自由类型按名称哈希落 8 色盘）、方向箭头、阶段与已结束虚化；画布上方补「搜索 + 类型筛选 + 按章过滤」（默认只到最新章节，防剧透），下方补**关系清单**——按强度/起始章/类型排序、点一行高亮对应边、点人名直接跳角色卡、缺起始章的关系当场标出来；点节点聚焦它的一度关系、点边看详情、双指缩放与单指拖动平移；卡头可**导出 PNG**（2 倍分辨率）与**复制关系清单 markdown**（直接发给写手/审校）。数据侧只加可选字段 direction / phase / tags / stages（多阶段：同一段关系按章变质、强度升降），旧 relations.yml 一条不改照旧出图。
- **窄屏两处布局修正**（0.8.3）：写作风格档位按钮从折叠头移进正文区（头行换行时会裁切按钮），整篇仍随页面滚动；阅读页芯片行加层级与间距，章纲对照栏不再贴边压住「作战板/目标/节拍/角色」。
- **阅读页首帧空值修复**（0.8.2）：正文/章纲读取前加 detail 空值保护——首帧数据未到就渲染会让整个分区抛错（显示「该分区渲染出错」），现在首帧走骨架、数据到再渲染。
- **写作风格整篇可读**（0.8.1）：风格卡去掉内层滚动（手机上滑不到底的元凶），整篇随面板主区滚动一次看完；10 个档位按钮放进可换行容器，窄屏不再被卡片边缘截断。
- **语言档位扩到 10 档**（0.8.0）：大白话（默认）/ 文白相间 / 古风 / 爽文快节奏 / 冷硬悬疑 / 细腻言情 / 都市幽默 / 史诗厚重 / 冷峻极简 / 治愈日常。档位清单由 `templates/novel/style-presets/*.md` 动态扫出，新增文件即出现在「写作风格」tab 的按钮里；套用只替换 style.md 的「## 语言」节，其余节不动。开书冷启动第一问就用 ask_user_question 让作者选档位。
- **执行层降本**（0.7.1）：审校与素材调研员补上上下文压缩与工具输出裁剪（此前没有，长任务越跑越贵）；全部角色工具输出上限 32KB → 16KB；写手 ≤40 步、去AI味师 ≤30 步、其余角色保持 ≤40 步；审校报告改成「结论 / P0-P2 / 未核实」三段硬模板；主编新增「派活前 list_agents 回收」与「看 edit 次数判碎改」；/state 走 gzip（204KB → ~35KB），门禁分改分片拉取（首屏 6 章，1.2s 后补余下）；ledger 增加「未来 3 章到期」提示；预设摘掉 plan-mode，少注入一段英文工具说明。
- **勾选导出 + 账目对账单**（0.7.0）：章节表多选后可一键导出**勾选章节**为 TXT 或 Word（.docx 零依赖自建，标题/章节名/正文段落三段式，Word、WPS、LibreOffice 都认）；文本来源与阅读页同源，只搬选中章、不动其他；CLI 对齐：`xiaoyu-novel export --format docx --chapters 1,3,5-7`。设定管理员新增一条命令 `xiaoyu-novel ledger [dir] [--chapter N] [--json]`——一条命令算出「本章应落盘（出场记录/伏笔/时间线/记忆）+ 全局缺口（超期伏笔/从未出场角色/五账计数）」，替代逐份通读五本账；写手侧补「超长章（>6000 字）分两段写、被截断从中断处续写」。
- **写作台 2.0**（0.6.0）：阅读页新增「作战板」——章纲节拍逐条勾选、本章要埋/要收的伏笔、出场角色与口吻、本章目标字数、重复词统计、节拍落地核对（命中率低于 40% 标黄）；「专注」模式藏起顶栏与清单，只留标题、正文、字数；底部动作条（保存 / 上一章 / 下一章 / 作战板 / 专注）固定拇指区，手机上写整章不用回顶部；顶栏补「上一章」「选章」与左右滑翻章；「历史」按章保留最近 30 份旧正文，点开可载入编辑器再存；「搜全书」支持正文与章纲多词搜索、全书替换（逐章 base_hash 冲突检测，历史版本可回滚）；`Ctrl/⌘+K` 命令面板、`Ctrl/⌘+Shift+F` 直接开搜；章节表多选批量改状态；概览新增最近 7 天写作曲线。写崩了、手机杀进程也不怕：每 800ms 把草稿写进本地，下次打开亮「恢复草稿」条。
- **越写越快**：读盘走三层缓存（进程内读缓存按 mtime+size 校验、章节解析备忘、快照缓存 1.2s TTL + 全文件签名），书涨到上百章时开面板不再重读整本书；写盘/删除自动失效，外部改动最迟 1.2s 被发现。自动保存变密后，写盘触发的整份快照重拉合并到停手 1.2s 一次，连续码字不再每次保存都重扫全书。
- **手机可用**：面板按实例实宽做容器查询（overlay 中栏 / 右栏 tab / 拖窄的右栏都算），≤640px 自动收拢——整页不再横向滚动、章节表砍掉「卷·章」与「梗概」只留四列、可点控件统一 30px 一档、阅读页标题独占一行动作折行、弹层与全屏编辑铺满；≤440px 看板与开书清单转单列、摘要行让位。手机竖屏 360px 下从概览到阅读、编辑、门禁全流程不用横滑。阅读页里**正文与章纲对照同一套折叠范式**：各有一行「标题 · 字数」头，点一下收、再点开——两条框共用 `--myt-box-h`（默认 40vh），框内各自滑动、字号 14/24 便于阅读，两个头都留 38px 触控高度。**长文块也是同一范式**（0.4.11）：分卷规划、写作风格基准、时间线、索引板两列、伏笔看板都收进可收起/展开的带边框方框，框内自己滚（`overscroll-behavior: contain`，滑到底不带走整页）；设定/科学/调研的单条长描述用矮一档的方框（22vh）。阅读页顶栏带「下一章」，读完一章一步跳下一章（末章禁用并说明）。
- **CLI 兜底**：`xiaoyu-novel init / stats / index / export / brief / check / gate / report / audit / undo / progress / setup` 十二条零依赖命令管脚手架、统计、索引重建、导出、写作卡打包、静态体检、门禁评分（可 `--fail-under` 做 CI 闸门）、全书质检报告、全书体检、自动修撤销与写作进度。

## 快速开始

前置：**Node.js ≥ 18**、已装好的 DSH host（**0.1.7+**，见「兼容面」）。面板门禁分内置纯 JS 引擎，不需要 python3（检测器指标回归：node scripts/calibrate.mjs）；CLI 与写手用的扫描脚本仍需 python3，没有时装门禁退化为按配比表人工自检，流程照走。

npm 通道（发布到 registry 后可用；当前是私有发行，请直接走下面的离线包）：

```bash
dsh plugin --profile web add dsh-xiaoyu-novel
```

离线安装（DSHA / Android，未发布 npm 时用这个）：

```bash
dsha-plugin import /sdcard/Download/dsh-xiaoyu-novel-0.2.4.zip
```

（安装包随 GitHub Release 提供，详见 INSTALL.md。）

**重启 DSH（`dsh web`）**：插件启动时自动把预设装进 `~/.dsh/.agent-presets/xiaoyu-novel/`，并写好声明行托管块，无需再点任何按钮。托管块写入层自动选择：桌面/服务器默认写 home 级 `~/.dsh/cordis.patch.yml`；Android compat 壳环境（该壳每次启动会把 home 级 patch 重写坏）自动改写 profile 级 `~/.dsh/profiles/<name>/cordis.patch.yml`——壳不碰 profile 层，插件每次启动补写自愈，并顺手清掉 home 级遗留托管块防双声明；也可用环境变量 `DSH_XIAOYU_PATCH_LAYER=home|profile` 强制指定。新会话的预设选择器里选「**小鱼创作 (Xiaoyu)**」即可开写；要设为默认，在 Settings → Agent Presets 里选。

开发检出（想改插件或预设源码）用 link 形态直连仓库，改动经重启生效：

```bash
git clone https://github.com/lifangjin/dsh-xiaoyu-novel.git
dsh plugin --profile web add link:"$PWD/dsh-xiaoyu-novel"
```

只要命令行工具、不装插件的读者：零依赖 CLI 单独可用，`npx` 即跑，或装成全局命令（均为 npm 通道，与插件互不相干）：

```bash
npx xiaoyu-novel init                 # 免安装直接跑
npm install -g dsh-xiaoyu-novel       # 或装成全局 xiaoyu 命令
```

## 怎么用

选好预设后，对主编说话即可，它按工作流自己路由：

**开新书（Collab 四步共创）**：

> 我想写一本东方玄幻，主角靠「听懂器物说话」的金手指鉴宝升级。

主编与你逐项对齐设定（题材、金手指、基调、主角三要素、对抗主线），设定管理员落盘核心角色卡与世界观条目后交你拍板；大纲师出分卷规划再交你拍板——设定与分卷都定了，才动笔黄金三章（立世界钩子、立主角动机、立核心冲突）交付。

**逐章写作（Writing 七步法）**：

> 第三章可以开写了吗？

主编做衔接检查，委派大纲师出本章大纲（含五维叙事字段），过目后派写手写正文、审校审稿（清单 + 一致性扫描：冲突/时间线/伏笔/设定 + 连贯六维：行为/因果/资源/身份/伤势/战力），有问题回写手修，通过后由设定管理员一次跑完定稿维护（章纲对照 + 五本账 + index 重建 + 一致性核对，全部落盘才置 accepted）——你只需要在决策点拍板。

**集中审查**：

> 前 20 章做一次一致性检查。

主编推进 phase 到 consistency，审校扫描冲突/时间线/伏笔/设定与连贯六维（行为/因果/资源/身份/伤势/战力），问题按严重度排好交回写手。

用户回「ok / 可以 / 继续」即视为确认，主编直接推进，不复述确认。

## 创作台面板

DSH 左侧栏底部点「**小鱼创作台**」打开创作台（改文件、跑流程之外，给肉眼看的驾驶舱）。打开方式在面板系统设置里三选一（立即记忆，对下一次打开生效）：

- **分栏**（默认）：创作台在中栏全页，点章节/最近更新开**文章页右侧栏 tab**——阅读/编辑与创作台同屏对照；
- **中间栏**：两者都在中栏（0.1.25 及以前的唯一形态）；
- **右侧栏**：两者都在右侧栏 tab（需 DSH 0.2.x；0.1.x 宿主设置里右栏两项置灰，一切按中间栏走）。

右侧栏 tab 切走/切会话/收栏都不卸载（草稿保活），重新打开即拉最新内容；文章页换章仍重挂编辑器，但换章/返回前会先自动落盘，卸载瞬间还有一道急救保存——不再靠「30 秒窗口」赌运气。中栏形态行为不变：

- **章节**：状态筛选 + 按单写作清单；点章节进整页阅读——返回按钮、章纲对照（Markdown 渲染）、正文与章纲就地编辑保存（正文 textarea 自动保存——待写空章节与写作中（status=writing）章节打开即直接进编辑器、停手约 1.5 秒自动落盘（连续写作每 6 秒也强制落一次）、Ctrl/⌘+S 立即保存、切后台/失焦立即保存、手动/自动保存都停留在编辑态续写、回车换行自动加段首两个全角空格缩进、编辑栏实时显示正文字数（不含标点/含标点双口径）、章节标题可在编辑器顶部修改（与正文一次原子保存）、编辑器带行号（逻辑行号、随软换行对齐）、编辑器字号可缩放（A−/A+，localStorage 记忆）、编辑器字体可选（下拉：系统默认+黑体/宋体/楷体/仿宋/霞鹜文楷，阅读与编辑同源生效，localStorage 记忆）、可全屏编辑（Esc 退出）、阅读模式一键返回只读（脏稿先确认）；章纲 textarea 手动保存；文件在编辑期间被外部改过时拒绝保存并放回磁盘最新内容，不覆盖人工改动）、五维叙事字段、一键状态流转。
- **概览**：书稿卡右上「编辑」按钮展开 project.yml 的书名/作者/题材/篇幅/语言/工作流阶段/共创模式/简介表单化编辑（原「小说设置」tab 并入），保存保留文件里原有注释；表单载入后 project.yml 被外部（作者手改 / agent 推进阶段）改过时拒绝保存并提示重改，不覆盖人工改动。概览另设「分卷规划」卡，列出 volumes.yml 各卷定位与计划章节范围——拍板过的分卷有处可查，卡头「编辑源文件」可整文件编辑 volumes.yml。
- **受管文件写面**：角色/设定/科学设定卡与六本账本（关系/时间线/记忆/线索板/伏笔/分卷）均可从面板编辑源文件——墙头「新建」、卡详情「编辑源文件/删除文件」、各账本卡头「编辑源文件」（时间线/关系图空态也给入口）；保存时结构校验（账本须是条目数组、实体卡须带 frontmatter 围栏，不合即拒存），外部改动保护与正文编辑同口径；章节阅读页可新建章纲（本章目标/节拍/出场角色/需埋需收伏笔/与前章接口五件骨架预填）、删除章纲与删除章节——删除均确认弹层，不可逆，后悔靠 git，静态体检会把孤儿引用标出来。
- **顶栏**：当前版本号常驻；npm 上有新版时亮「有新版 ↗」徽章直连发布页，旁边「一键升级」按钮直接用 pnpm 把最新包装进当前 DSH 档（仅支持 profile 目录安装，pnpm 缺失时自动回落 corepack；检测到全局 `xiaoyu` CLI 时顺带以同一精确版本更新，未装则跳过；装完需重启 DeepSeek 才生效）；「检测更新」按钮只在无新版时显示（有新版时收起，让位给徽章与「一键升级」），点击手动现测线上最新版（绕过 1h 缓存——面板打开时只自动拉一次，页面开久了也不聋）；版本区后的齿轮打开系统设置，界面语言中文/English 可切、字号六档（100%–150%）整体缩放、打开方式三选一（分栏/中间栏/右侧栏），均立即生效并记忆。

面板写状态（章节状态、project.yml、index.yml 重建），正文/章纲/账本/实体卡等全部人工编辑入口只给人用（hash 旧版检测 + 结构校验，外部改动一律拒绝覆盖）——agent 的创作边界不变：共创模式下正文永远归作者与主编。

## 共创模式（作者亲笔）

不是谁都想让 AI 代笔。project.yml 的 `mode` 键决定正文归谁写，三种模式一句话：`ai-draft`（默认）AI 代笔，走 Writing 七步法；`co-write` 逐章指派谁写，主编动笔前先问清本章归谁；`author-draft` 全书作者亲笔，小鱼只备料、审稿、记账，永不代写。

author-draft 下的协作循环——你只管写，交稿即接管杂务：

> 第 5 章写完了，贴给你。（正文直接粘进对话，或者说一声第 X 章写完、指个文件）

主编收稿后你会拿到三样东西：**审校意见清单**（只挑问题、不代改，改不改随你）、**账本回填**（伏笔/时间线/关系/记忆/线索五本账按你正文实际发生的记，计划外的改动也能认领，来源标 `backfill`）、**下一章章纲**（`novel/outlines/vXX-cXXX.md`，拿着就能写）。圣域纪律：`chapters/` 正文唯作者可改，agent 至多更新 frontmatter 的 summary 与五维字段，且先建议后动手。

配套命令：`xiaoyu-novel brief <dir> <章号>` 打包写作卡（章纲 + 前章结尾 + 角色卡 + 活跃伏笔，带去任意编辑器或其他 AI），`xiaoyu-novel check <dir>` 做零模型静态体检（frontmatter 完整性、伏笔章号引用与超期、章纲钩子小节、时间线乱序、AI 味统计（句式重复/比喻密度/句长节奏）、拍板账校验等，不调模型——LLM 审校走主编）。

## 方法论技能

随插件带 6 个网文方法论技能，插件启动时安装器把它们落盘到 `~/.dsh/skills/`（即 `<home>/skills/`）下的 `xiaoyu-*` 六个目录，宿主技能面板可直接看到；大纲师、写手、审校、设定管理员按场景自动加载，你不用手动操作：

| 技能 | 一句话说明 |
|---|---|
| xiaoyu-golden-opening | 黄金三章：开篇四型选型、前三章职能分工（世界钩子 → 动机确立 → 冲突引爆）、对抗格局聚焦与金手指原则、前 300 字出事原则、信息释放纪律与自检清单 |
| xiaoyu-beat-pacing | 爽点节奏：即时正反馈环、期待感管理、爽点类型库与打脸节拍配比、压抑-释放配比、三级节奏曲线与章尾钩子选型 |
| xiaoyu-review-checklist | 审校清单：语言/节奏/人设/逻辑/伏笔/剧透/风格七层逐项检查，按 P0/P1/P2 三档严重度输出 |
| xiaoyu-foreshadow-discipline | 伏笔管理：铺垫与伏笔之辨、埋设即登记、推进节奏排期、回收「意外 + 合理」标准与台账清理阈值 |
| xiaoyu-suspense-craft | 悬疑与对比：悖论式悬念、悬念-行动-线索循环、信息差四象限、堵死猜测与对比表现力技巧 |
| xiaoyu-volume-craft | 卷纲与单元结构：卷四定（主题/收获/上限/刻度）、情节五步循环、支线字数红线、换地图纪律、群像戏份账与期待线并行 |

安装器只认 `xiaoyu-*` 前缀目录，`~/.dsh/skills/` 下你自己的技能一个字节不动。卸载插件后技能目录需手动清理（六个目录一起删）：

```bash
dsh plugin --profile web remove dsh-xiaoyu-novel
rm -rf "${DSH_HOME:-$HOME/.dsh}/skills/"xiaoyu-*
```

## novel/ 数据规范

`novel/` 目录是整个插件的数据库：project.yml（元信息与七阶段 phase）、style.md（写作风格基准）、volumes.yml、chapters/（frontmatter 五维叙事字段 + 正文）、characters/（角色卡）、world/、science/（三色设定）、relations.yml、foreshadows.yml（伏笔状态机）、timeline.yml、memories.yml（出场记录、承诺账、卷级梗概）、clue-board.yml、decisions.yml（拍板账）、research/、exports/。全部格式、示例与设计理由见：

- 速查版：项目初始化后的 `novel/README.md`（模板源 [templates/novel/README.md](templates/novel/README.md)）
- 完整版：[docs/spec.md](docs/spec.md)（为什么不用 SQLite、五维字段定义、伏笔状态机语义、出场记录约定）

## CLI

```bash
xiaoyu-novel init [dir]     # 生成 novel/ 脚手架（默认 ./novel；已存在文件一律跳过，绝不覆盖）
xiaoyu-novel stats [dir]    # 逐章 CJK 字数、状态分布、当前 phase
xiaoyu-novel index [dir]    # 从 volumes.yml + chapters/ 重建 index.yml（派生文件）
xiaoyu-novel export [dir]   # 导出全书：--format md|txt|epub（默认 md），--out <目录> 改输出位置
xiaoyu-novel brief [dir] <chapter>  # 组装单章写作卡（章纲+前章结尾+角色卡+活跃伏笔）；--out 落盘，缺省 stdout
xiaoyu-novel wc [dir] <chapter> [--json]  # 单章轻量自检：去空白字数/CJK/感叹号/引号配对/禁项/长句/人味指数与硬伤（写手交稿前用，只读）
xiaoyu-novel check [dir]    # 静态体检（不调模型）：frontmatter/枚举/章号/伏笔引用与超期/章纲钩子/AI 味统计/时间线年份/关系卡引用/拍板账校验/phase 就绪判据
xiaoyu-novel clean [dir] [--apply] [--undo] [--json]
                            # 清账本：超长条目压成结论（明细进 archive/ledger-details/）、已写【推进章】的
                            # 超期伏笔升 progressing；默认 dry-run，写前备份，--undo 还原上一次
xiaoyu-novel gate [dir] [--fail-under N]  # 门禁分：逐章人味/人写/章末平收，按低分排序；有未过线章节退出码 1（可接 pre-commit）
xiaoyu-novel report [dir] [--out <文件>]  # 全书质检报告（markdown）：逐章分数、章末钩子、高频病灶、优先返修清单
xiaoyu-novel audit [dir] [--json] [--out <文件>]  # 全书体检：跨章重复、角色出场、章纲未落地、字数离群、连续平收
xiaoyu-novel undo [dir] [章节]  # 撤销最近一次自动修（逐句改 / 整章改都有快照，每章保留 10 份）
xiaoyu-novel progress [dir]     # 最近 30 天写作进度（每日总字数 + 今日新增）
xiaoyu-novel setup [dir]        # 开书九件套检查（逐项 ✓/缺，缺项退出码 1）
```

export 示例：

```bash
xiaoyu-novel export novel                      # Markdown，落到 novel/exports/
xiaoyu-novel export novel --format txt         # 纯文本
xiaoyu-novel export novel --format epub        # EPUB 3（零依赖打包，可直接导入阅读器）
xiaoyu-novel export novel --format epub --out ~/Downloads   # 换输出目录
```

输出目录默认 `<dir>/exports/`，文件名 `<书名>-<YYYYMMDD>.<扩展名>`（书名取 project.yml 的 title）；章节解析与 stats/index 同一套逻辑，frontmatter 不会混进正文。

零依赖（node:fs/path/url/crypto），任意 cwd 可用。装法三选一：`npm install -g dsh-xiaoyu-novel`、随用随取的 `npx xiaoyu <命令>`、或开发机的 `npm link`（仓库检出即改即生效）。三样都没有时 `node <插件目录>/bin/xiaoyu.mjs` 等价（dsh 插件安装也会把包落进 profile，可直接指过去）。日常写作中 index.yml 由设定管理员直接重建，CLI 主要给人用。

## 卸载

```bash
dsh plugin --profile web remove dsh-xiaoyu-novel
rm -rf "${DSH_HOME:-$HOME/.dsh}/.agent-presets/xiaoyu"
rm -rf "${DSH_HOME:-$HOME/.dsh}/skills/"xiaoyu-*
```

宿主是 DSH 0.1.7+ 时再补一步：删去 `~/.dsh/cordis.patch.yml` 里的 dsh-xiaoyu-novel 托管块（`# --- dsh-xiaoyu-novel preset managed (auto-generated; do not edit) ---` 到 `# --- end dsh-xiaoyu-novel preset managed ---` 之间的整段，含两行标记），免得留下指向已删目录的声明行；Android compat 壳上托管块写在 profile 层，`~/.dsh/profiles/<name>/cordis.patch.yml` 里的同名托管块也照此删除。`novel/` 目录是你的书稿，卸载插件不会动它。

## 兼容面

插件启动时读宿主版本，按版本自动选择委派行形状——**宿主升级后重启即切换，无需重装插件**。版本探测是五级探针（argv[1] → 全 argv 扫描 → app.asar / desktop-runtime → Electron API → home 全局兜底），前四级锚定当前进程的真实宿主，`<home>/node_modules/@deepseek-ai/dsh/package.json` 那份 home 全局安装只做最后兜底（老 CLI 残留可能陈旧几个大版本）；每级读到了什么可查创作台面板的 `host-debug` 端点（路径已脱敏）：

- **DSH 0.1.7 – 0.2.1-rc.1 → v1 内联形状**：5 个角色委派行直接内联 persona 与 toolFilter，托管块 1 条声明行。
- **DSH 0.2.1-rc.2+ → v2 AgentPreset 形状**：该版本起 dsh-tool-subagent 拒绝内联 persona/toolFilter，插件改用 [presets/xiaoyu-novel/agent.cordis.v2.yml](presets/xiaoyu-novel/agent.cordis.v2.yml)——托管块写 6 条声明行（主编 preset + 大纲师/写手/审校/设定管理员/素材调研员 5 张角色 preset），主编委派行以 `agentPreset` 指向角色 preset，角色的工具面由 preset 里的实体工具行承载（审校只读、考据带联网检索）。
- **DSH 0.2.2-alpha.2+ → v2 形状剥离 list-agents 行**：0.2.2 起宿主把 `list_agents` 工具并入 `@deepseek-ai/dsh-tool-subagent-control` 主导出并删除 `./list-agents` 子路径导出——旧声明行在 0.2.2+ 上模块解析失败，注册表审计会把整张主编 preset 判 broken、从选择器消失（issue #7，0.2.2-rc.1 实测复现）。组装时按宿主版本自动剥离该行（list_agents 能力无损，由 control 主导出自带注册）；0.2.1 系宿主不受影响，声明行照旧保留。
- **角色预设会出现在预设选择器**（宿主对预设没有隐藏机制），name 带「（内部）」标明：日常写作由主编委派自动选用，不经主编、想单独开一个写手/考据会话时直接选中即可。
- 两种形状的 persona 文本同源逐字一致（[test/composition.test.mjs](test/composition.test.mjs) 逐字节把关）；宿主版本完全未知（五级探针全败）时不写声明行、预设文件照落走 partial 自愈，绝不把可能已 ≥0.2.1-rc.2 的宿主声明成 v1 内联（下次启动版本可读时自动补写）。
- ≤0.1.6 的目录扫描轨道：不做（宿主已淘汰）。
